# TrustShield AI — Offline / Static Build

A fully working local copy of TrustShield AI that runs on nothing but
**Python, Node.js, and a web browser** — no database server, no API keys,
no internet access at runtime, no GPU, no heavy ML downloads. Every value
a live LLM, judge panel, or the audited AI's own endpoint would normally
produce is instead generated by a deterministic engine seeded by each AI
system's own registration answers — so different registrations genuinely
produce different, reproducible-looking results, and you get a full
click-through walkthrough with real business logic running the whole way.

## One-time setup

### 1. Backend
```bash
cd backend
python3 -m venv venv                            # Windows: python -m venv venv
./venv/bin/pip install -r requirements.txt      # Windows: venv\Scripts\pip install -r requirements.txt
```

### 2. Frontend
```bash
cd frontend
npm install
```

That's it — no database to create, no service to start.

## Running it

From the **project root** (one level above `backend/` and `frontend/`):
```bash
npm run dev
```
This starts both servers together in one terminal (colored `[backend]` /
`[frontend]` log prefixes). `Ctrl+C` stops both.

Open **http://localhost:5173**.

(If you'd rather run them separately in two terminals, that still works —
`uvicorn app.main:app --reload` in `backend/` with the venv active, and
`npm run dev` in `frontend/`.)

## Suggested walkthrough

1. Log in (demo account or your own).
2. **Register AI** — fill out the wizard. Try two contrasting profiles to
   see the effect on audit results: one "Fully automated — no human
   review" + "Approvals" system, and one "Human-in-the-loop" +
   "Informational only" system.
3. Under that AI system, upload the sample data in `sample_data/`:
   - `acme_claims_interaction_logs.csv` under log ingestion
   - `acme_claims_knowledge_base.md` under knowledge base upload
4. Run a **Black Box Audit** (API mode — any placeholder endpoint/API key
   works, the call never leaves the process). Compare the two systems'
   scores — registration answers visibly drive the outcome.
5. Run a **Governance Evaluation** to see the SDCC metrics/detection
   confidence computed from the ingested logs.
6. Open **Report**, **Dashboard**, **Executive Summary**, **Risk
   Intelligence**, and **Recommendations**.
7. Try **Chat**, the **TAF Taxonomy** Excel export, a **self-attestation
   document** upload (Report Audit), and **Rerun Comparison**.
8. Check **Admin Panel** for the cross-user view.

## How it works

| Layer | Status |
|---|---|
| TAF taxonomy, scoring, aggregation, control mapping | **Real** — untouched original code |
| Registration form → probe selection → posture-driven outcomes | **Real** — registration answers (oversight model, decision influence, end users, etc.) drive a computed "safety posture" that determines audit outcomes |
| Storage | **Real, just different** — plain JSON files under `backend/data/`, one per collection, instead of Postgres. Auto-created on first run |
| Readability / sentiment / PII / fairness metrics | **Real, heuristic tier** — pure-Python fallbacks (see `analysis_engines.py` / `metrics_calculator.py`); no heavy ML libraries installed or needed |
| Primary LLM calls, 3-judge panel, Phase-4 detector | **Synthetic** — `app/services/offline_engine.py`, deterministic and registration-aware |
| "Call the audited AI" (API mode and UI/Playwright mode) | **Synthetic** — simulated target-AI responses, category-matched so scoring behaves correctly |

Flip `OFFLINE_MODE=false` in `backend/.env` and supply real API keys any
time to go back to live behavior.

### Tuning knobs

- `backend/app/services/offline_engine.py` → `SCORE_BOOST` (default
  `0.12`) — shifts every audited system's scores up or down. `0.0` = no
  change, higher = everything reads safer.
- `backend/app/services/sdcc/detector.py` → `OFFLINE_MIN_DETECTION_CONFIDENCE`
  (default `0.55`) — the floor for SDCC's detection-confidence readout.
- `frontend/src/pages/Dashboard.tsx` → `OFFLINE_PHASE_DURATIONS_MS` — the
  audit-progress modal's per-phase timing (currently totals ~8.5s).
- `frontend/src/index.css` → `--font-display` — the app's heading font
  (see `--font-sans` in `tokens.css` for body text).

### Dependencies

Trimmed to the minimum that still gives the full app experience — see the
comments at the top of `backend/requirements.txt` for exactly what was
left out and why (mostly: real network SDKs like `openai`/`httpx`/`requests`
that OFFLINE_MODE never calls, and optional ML libraries the code already
has pure-Python fallbacks for). Nothing here needs a GPU, a model
download, or internet access at runtime — only to `pip install`/`npm
install` once.

### Notes on this port

- No outer project scaffolding (`package.json`, `requirements.txt`,
  `vite.config`, `.env`, etc.) was in the original export — reconstructed
  from the actual imports used in the code.
- `backend/app/services/taf/excel_export.py` was missing from the
  original export — rewritten from scratch using `openpyxl`.
- Storage was migrated from PostgreSQL to plain JSON files
  (`backend/app/database.py`) — same collection-style API
  (`find`/`insert_one`/`update_one`/etc.), so the rest of the app didn't
  need to change. A handful of files that used to run raw SQL directly
  (`ai_routes.py`, `blackbox_routes.py`, `taf_routes.py`,
  `log_normaliser.py`, `audit_evidence.py`) were rewritten to use that
  same API instead.
- Fixed a handful of pre-existing bugs found while testing, unrelated to
  the offline conversion itself: several endpoints called `.sort().limit()`
  chained onto an already-materialized list (a leftover from an earlier
  Mongo→Postgres migration) and always crashed; and SDCC's detection
  confidence was written under the key `det_conf` but read back under a
  different key, `detection_confidence`, so it always silently showed 0%
  regardless of how confident the real detector was.
- `frontend/src/pages/_rc.tsx` is dead code — an orphaned draft that
  duplicates `Report.tsx`, never imported anywhere. Excluded from the
  TypeScript build via `tsconfig.json`; left in place untouched.
- Fonts (Inter, Manrope, Plus Jakarta Sans, JetBrains Mono) are
  self-hosted via `@fontsource` packages, bundled at build time — the
  original code pulled them live from Google's font CDN, which silently
  fails (and falls back to a generic bold system font) on a machine
  without a live connection to it.

Every feature described above was tested directly against a running
instance of this exact build — not just assembled and assumed to work.
